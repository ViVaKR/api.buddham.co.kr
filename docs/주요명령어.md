## 앱수정후 처리 순서

```bash
# 지금처럼 이미지 태그를 buddham-api:net10처럼 고정해서 쓰시면, docker build → k3s ctr images import까지는 잘 되는데, kubectl apply만 다시 치시면 아무 일도 안 일어납니다. 이유는 Kubernetes가 apply를 할 때 yaml 파일 내용과 클러스터에 이미 적용된 스펙을 비교하는데, image 이름과 태그가 토씨 하나 안 바뀌었으니 "변경사항 없음"으로 판단해서 파드를 재시작 안 시켜버려요. 컨테이너 안 비트는 새로 들어왔는데, 파드는 옛날 이미지를 그대로 물고 계속 돌고 있는 상태가 되는 거죠.
# 그래서 정확한 시나리오는 이렇습니다.

# 1. 소스 수정
docker build -t buddham-api:net10 .
docker save buddham-api:net10 | sudo k3s ctr images import -
kubectl rollout restart deployment/buddham-api-deploy -n buddham ← 이게 빠진 핵심 단계
kubectl rollout status deployment/buddham-api-deploy -n buddham 으로 롤아웃이 끝까지 잘 굴러갔는지 확인

# 2. 로그 확인 (지난번처럼)
kubectl logs -l app=buddham-api -n buddham --tail=50

# rollout restart는 Deployment에 타임스탬프 annotation을 하나 박아서 강제로 "스펙이 바뀐 척" 만들어주는 명령이에요.
# 그러면 파드가 새로 뜨면서 containerd가 그 태그에 대해 로컬에 새로 import된 이미지를 가져다 씁니다.
# IfNotPresent는 "원격 레지스트리에서 새로 안 당겨온다"는 뜻이지
# "로컬에 갱신된 이미지를 안 본다"는 뜻이 아니라서, 이 흐름이면 정상 작동해요.
# 참고로 좋은 점 하나는, api가 replica 2개라 rollout restart해도 한쪽이 떠 있는 동안 다른 쪽이 교체되는 RollingUpdate 방식이라 다운타임 없이 자연스럽게 넘어갑니다.
# ai, chat은 replica 1개라 그 잠깐 사이엔 살짝 끊길 수 있어요 — 지금 단계에선 큰 문제 없겠지만, 나중에 트래픽 늘면 이쪽도 2개로 늘리시는 걸 고려해보세요.
# 그리고 셋 다 한꺼번에 안 건드리셔도 돼요. api만 고치셨으면 api만, ai만 고치셨으면 ai만 build/import/restart 하시면 됩니다.
# 마지막으로 보험 하나, 혹시 배포했는데 뭔가 터지면 이전 버전으로 즉시 되돌릴 수 있어요.

bashkubectl rollout undo deployment/buddham-api-deploy -n buddham

# 다만 이건 같은 태그를 계속 덮어쓰는 방식이라 "이전 버전"이 사실 똑같은 태그의 새 이미지일 수도 있어서 완벽한 롤백은 아니에요.
# 나중에 여유 생기시면 태그에 git commit hash나 날짜(net10-20260621)를 붙이는 방식으로 바꾸시면,
# 매번 yaml의 image 줄도 같이 바뀌니 apply만으로 롤아웃되고 진짜 의미있는 롤백 히스토리도 생깁니다.
# 지금 1인 개발 단계에선 굳이 서두르실 필요는 없고, 나중에 팀이 커지거나 운영 트래픽 생기면 그때 챙기셔도 충분해요.


```

```bash
sudo kubectl delete deployment buddham-ai-deploy buddham-api-deploy buddham-chat-deploy -n buddham
sudo kubectl apply -f buddham-app.yaml


# Deployment 롤아웃 재시작 (containerd에 이미지 있으니 이제 될 거야)
sudo kubectl rollout restart deployment buddham-ai-deploy -n buddham
sudo kubectl rollout restart deployment buddham-api-deploy -n buddham
sudo kubectl rollout restart deployment buddham-chat-deploy -n buddham

# 상태 확인
watch kubectl get pods -n buddham
```
